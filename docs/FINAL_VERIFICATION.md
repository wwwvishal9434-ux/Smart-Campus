# Final Verification Report

What was run, what passed, what was found and fixed, and what is still untested.

| Layer | What ran | Result |
|---|---|---|
| Unit tests | `cd server && npm test` (no database) | **17 / 17 pass** |
| Database | PostgreSQL 16, schema from `prisma/migrations`, full seed (`npm run seed -- --reset`) | seed completes: 16 students, 1350 attendance rows, 96 results, 7 jobs, 20 applications |
| API integration | `npm run test:api` on the seeded database | **16 / 16 pass** (auth, authorization, CRUD, attendance, notes upload/download byte-for-byte, assignments, exam scoring, results, placements, notifications, events, contact; every dashboard/list endpoint returns 200 for the right role) |
| Route audit | every one of 89 routes called as anonymous, student and admin | all return the correct 401/403 |
| Client/server match | every API call the React client makes | all exist on the server |
| Browser crawl | headless Chrome, real login through the form, 27 pages (16 admin + 11 student) at 1280 px, 375 px and dark mode (1024 px) | no console errors, no failed API calls, no horizontal overflow at 375 px, dark class applied |
| Browser journey (11 steps) | register through the form; form validation messages; edit profile; upload an assignment file; ineligible job blocked, then eligible after results added; apply through the modal; take an exam (timer, navigation, confirm, server score, PASS); single-attempt block; **1-minute exam auto-submits at zero**; admin sees the new applicant | **11 / 11 pass** |
| Production build | `cd client && npm run build` | passes |
| **Single-server mode** (what Render runs: the API serves the built website) | 27-page crawl and the full 11-step browser journey repeated against `http://localhost:5000` with Helmet's strict Content-Security-Policy | no console/CSP errors, 11 / 11 pass; deep links like `/student/exams/x/take` load; unknown `/api/...` still returns JSON 404 |
| First-boot data load | migration SQL applied to a fresh empty database, then `node prisma/seed.js` twice | first run seeds everything with a production-style password; second run skips safely (exit 0) |

> **Caveat.** Prisma's normal engine binaries could not be downloaded in the test environment, so the tests ran Prisma 6.19 with its JavaScript query engine through the `pg` driver adapter. Queries, schema and migrations are identical, but your first run with Prisma's default engine is the final confirmation.

## Bugs found by running it (all fixed)

1. `schema.prisma` used one-line enums and a one-line generator block, which Prisma rejects. The schema would have failed `prisma validate` on the first run. Fixed; schema now validates.
2. The seed script sent a field (`fileSize`) that the submissions table does not have; the seed failed on real PostgreSQL. Fixed.
3. The student dashboard pie chart coloured slices by position, so "MISSED" appeared green. Now each status has its own colour, with a legend.
4. A past-deadline assignment (late submissions allowed) appeared under "Upcoming deadlines" without warning. The panel is now "Pending assignments" and shows an OVERDUE badge.
5. The API integration tests left test data in the database; they now delete everything they create.
6. The test-route parser missed routes written several-per-line (found while building the route audit); fixed.
7. Prisma migration files did not exist; `prisma/migrations/20261101000000_init` is now included (generated by Prisma from the schema).

## Known gaps (not hidden)

Not implemented: profile photo upload, Settings page, company logo upload, teacher login, exam closing time, cloud file storage, frontend unit tests.
Not tested here: `prisma migrate deploy` itself (the test environment's JavaScript schema engine cannot read PostgreSQL's `name` type, so the same migration SQL was applied with `psql` instead; Render uses Prisma's normal engine) and the Render build. Not yet tested: admin add/edit/delete modals and the attendance, notes, assignment and exam *creation* screens by clicking; password-reset link flow in the UI; print preview of results; auth rate limit (429); cross-course download block in the UI; deployment to Vercel/Render/Neon (needs your accounts).
