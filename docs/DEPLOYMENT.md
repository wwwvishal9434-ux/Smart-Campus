# Deployment Guide

> **Easiest route:** follow [`../DEPLOY_NOW.md`](../DEPLOY_NOW.md): one free Render service serves the website, API and database, with demo data loaded automatically. The three-service route below (Neon + Render + Vercel) is the alternative if you want the frontend on Vercel; for it, create the Render service manually as described in step 2 (do not use the Blueprint, because the root `render.yaml` is the single-service setup).

Target setup: **Neon** (PostgreSQL) + **Render** (API) + **Vercel** (frontend). Supabase or Railway PostgreSQL work the same way: you only need a connection string.

> The application was run end-to-end on a real PostgreSQL database and in a real browser before this guide was written (see `FINAL_VERIFICATION.md`). Still, do the local run in the README first and confirm login works, then deploy.

## 0. Migrations (already included)

`server/prisma/migrations/20261101000000_init/` contains the SQL for all 23 tables (generated by Prisma from `schema.prisma`). Render applies it automatically through `prisma migrate deploy` in the build command. After you change `schema.prisma` later, run `npx prisma migrate dev --name <change>` locally and commit the new folder.

## 1. Database (Neon)

1. Create a project at neon.tech and copy the **connection string** (it ends with `?sslmode=require`).
2. Use the **direct (non-pooled)** string for `DATABASE_URL`. Prisma migrations do not work reliably through a pooler.

## 2. Backend (Render)

1. Push the repository to GitHub.
2. In Render choose **New -> Web Service** and select the repo:
   - Root directory: `server`
   - Build command: `npm install && npx prisma generate && npx prisma migrate deploy`
   - Start command: `npm start`
   - Health check path: `/api/health`
3. Environment variables:

| Variable | Value |
|---|---|
| `NODE_ENV` | `production` |
| `DATABASE_URL` | Neon connection string |
| `JWT_SECRET` | random string of **32+ characters** (the server refuses to start with a shorter one in production) |
| `JWT_EXPIRES_IN` | `1d` |
| `CLIENT_URL` | your Vercel URL, e.g. `https://smart-campus.vercel.app` (comma-separate several origins if needed) |
| `UPLOAD_DIR` | `/tmp/uploads` on the free plan (or your disk path on a paid plan) |
| `SEED_ADMIN_PASSWORD`, `SEED_STUDENT_PASSWORD` | strong passwords, used only by the seed script |

4. **File uploads on the free plan.** Free Render services have no persistent disk, so uploaded notes and submissions disappear whenever the service restarts or redeploys (seeded demo notes too). Everything else keeps working. For permanent files either use a paid plan with a disk, or move uploads to cloud storage; only `server/src/config/upload.js` and the download handlers touch files, so that is a contained change.
5. After the first deploy, open **Shell** on the service and run `npm run seed` once to load the demo data. Seeding only works on an empty database. Change the admin password afterwards.
6. Check `https://<your-api>.onrender.com/api/health` returns `{"success":true,...}`.

## 3. Frontend (Vercel)

1. Import the same GitHub repo. Set **Root Directory** to `client`; Framework preset **Vite**.
2. Build command `npm run build`, output directory `dist` (the defaults).
3. Environment variable: `VITE_API_URL` = `https://<your-api>.onrender.com/api`
4. Deploy. `client/vercel.json` rewrites all routes to `index.html` so page refreshes on `/login` etc. work.
5. Copy the Vercel URL into `CLIENT_URL` on Render and redeploy the API, otherwise the browser will block requests (CORS).

## 4. Post-deployment checklist

- [ ] `/api/health` responds
- [ ] Login works as admin and student; wrong password is rejected
- [ ] Student cannot open `/admin/students`
- [ ] Upload a note and download it (it will vanish after a redeploy on the free plan; that is expected)
- [ ] Register a new student from the live site
- [ ] Dashboards show data
- [ ] Demo passwords changed

## Common problems

| Symptom | Fix |
|---|---|
| Browser console shows a CORS error | `CLIENT_URL` on Render must exactly match the Vercel URL (no trailing slash) |
| API returns 500 on every request | Check Render logs; usually a wrong `DATABASE_URL` or migrations not applied |
| `Missing env var` at startup | Set `DATABASE_URL` and `JWT_SECRET` on the service |
| Files disappear after deploy | Free plan has no persistent disk; see step 2.4 |
| First request after a while takes 30-60 seconds | Free Render instances sleep when idle; the first request wakes them |
